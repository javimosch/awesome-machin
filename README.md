# Awesome machin [![Awesome](https://awesome.re/badge.svg)](https://awesome.re)

A curated list of things built with **[machin](https://github.com/javimosch/machin)** — MFL, the Machine-First Language. machin compiles a terse, type-inferred, agent-friendly language to native code through C: small static binaries, no runtime.

> New machin app? Open a PR adding a one-line entry. Keep the list machine-first: terse, linked, current.

## The language

- **[machin](https://github.com/javimosch/machin)** — the compiler + language (MFL → C → native). Generics, closures, goroutines/channels (`select`, `close`, range, comma-ok), arena GC, C FFI, a `machweb` web framework, and a growing builtin surface (networking, native TLS + WebSocket, file I/O, SQLite, JSON + jq-style path queries, regex, base64, SHA-256/HMAC, `(value, err)` error handling).

> Organized by domain: **CLI tools & services**, **Game dev**, **Web**, **Crypto & protocols**. New repos follow a domain-scoped naming convention — `machin-game-demo-*` for games/graphics, `machin-web-demo-*` for web.

## Learning & reference

- **[machin-learn](https://github.com/javimosch/machin-learn)** — a **knowledge base for agents** learning MFL: seven skill files covering the language, builtins, gotchas/pitfalls, terminal/TUI, networking, storage/SQLite, and C FFI. Each skill is a self-contained `.md` an agent can load in one `read` call, with concrete examples and warnings for every caveat — designed to help budget models master machin fast.

## CLI tools & services

- **[poche](https://github.com/javimosch/poche)** — **[▶ docs](https://javimosch.github.io/poche/)** · an **agent-first headless CMS** (PocketBase-shaped, no Admin UI) in one MFL binary: typed schemas, RBAC tokens, schema-validated REST, realtime long-poll `/watch`, file blobs, optional `POCHE_CLOUD` multi-tenant signup via [peage](https://peage.intrane.fr). Storage is **[grange](https://github.com/javimosch/grange)** (not SQLite) — crash-safe WAL + indexes; `poche bench --n 100000` and live scenarios (bookstore / bank / car-renting). Full [cli-specs](https://cli-specs.intrane.fr/) (`guide` / `help-json` / `feedback` / `update`).
- **[machin-esetres](https://github.com/javimosch/machin-esetres)** — **[▶ docs](https://javimosch.github.io/machin-esetres/)** · *"es-tres"* (say it) — a **self-hosted S3-alternative object store**: buckets, sha256-content-addressed objects with refcounted dedup, an agent-first CLI/REST API, and a second front-end that speaks **real AWS SigV4** — `aws-cli`/`mc`/`rclone`/any S3 SDK point straight at it, verified against a genuine `aws-cli` (not a signer testing its own verifier), not just an "S3-flavored" API. **No new machin builtin** — SigV4 is pure MFL over the existing `hmac_sha256_bytes`/`sha256_bytes`, `machweb`'s binary-safe bodies do the rest. Built to give [poche-resend-webmail](https://github.com/javimosch/poche-resend-webmail)'s mail attachments a real, deduplicated home off one app server's disk.
- **[grange](https://github.com/javimosch/grange)** — a **machin-native document database**: agent-first (JSON-only stdout, semantic exit codes, `guide`/`help-json`), **crash-safe by construction** (every commit is one immutable sha256-trailered WAL chunk — `kill -9` provably leaves exactly the committed prefix), and **faster than SQLite on every indexed workload** at 100k docs: 278k inserts/s vs 25k with the same two indexes, indexed count and **group-by sum/avg in O(1)** via write-time aggregate registers (×1000 in <1 ms vs 49 s), sorted **range indexes** answering `score>=900` in O(log n) (<1 ms ×1000 vs 257 ms indexed). Embed the engine in any MFL app SQLite-style, drive the CLI, or run `grange serve` — an HTTP/JSON server that is **single-actor with zero goroutines**, so machin's inferred race analysis verifies the whole database race-free on every build.
- **[roam](https://github.com/javimosch/roam)** — **leave a working agent on a remote box**: an agent runtime you `scp` to a VM as one ~7 MB static binary. A hand-written **LLM tool-loop** (Anthropic + OpenAI-compatible wire shapes) with hard **iteration/token budgets**, a **workdir sandbox**, a **gated shell** (destructive commands park for async approval, with a **deny budget**), and an independent **goal-verify** judge before a `finish` is accepted. Also drives **Devin/SWE-1.7** as an engine (`--provider debri`) — a flat-subscription coding agent dispatched from the same CLI. Live-proven building real projects unattended.
- **[roam-panel](https://github.com/javimosch/roam-panel)** — **approve your remote agents from your phone**: the human touchpoint of the roam stack. Agents report in over HTTP; when one **parks on a destructive command** the panel **emails you one-tap signed Approve/Deny links** and shows a live mobile view — a **WebAssembly client compiled from the same MFL view code as the server** (isomorphic machin), with a no-JS server-rendered fallback. Multi-tenant, one self-hostable binary.
- **[roam-hub](https://github.com/javimosch/roam-hub)** — **[▶ live](https://hub.roam.intrane.fr/llms.txt)** · the **hosted half of the roam stack**: a control plane that **schedules, meters, bills, and reports** autonomous agent runs — "POST a spec, walk away, get a webhook." Pull-based workers (stock roam binaries; the protocol is engine-agnostic) hold **no model keys**: every LLM call proxies through the hub, which meters exact tokens, enforces a mid-run **budget cut-off** and a **kill switch**, and bills the **actual upstream generation cost** per run over [peage](https://peage.intrane.fr). Cron + webhook triggers (event payload injectable into the prompt), append-only run journals, typed-error JSON API, **no human web UI by design**.
- **[machin-terminal](https://github.com/javimosch/machin-terminal)** — **[▶ landing](https://javimosch.github.io/machin-terminal/)** · a **terminal emulator** in pure MFL (st-class, single-window): a raylib glyph grid driven by a hand-written **VT100/xterm parser** (alt-screen, scroll regions, SGR 16/256/truecolor, UTF-8 + box-drawing, **mouse reporting** X10/SGR) over a `forkpty` PTY. Hosts **vim, htop, and tmux** — tmux is the multiplexer, so there are **no native tabs/splits by design**. One ~1.1 MB static binary, no GTK/VTE. Exercises the **PTY + `ioctl` + `poll` + raylib** C FFI surface — the first non-game desktop GUI app in the ecosystem.
- **[machin-auth](https://github.com/javimosch/machin-auth)** — **[▶ live demo](https://auth.intrane.fr)** · a **self-hostable auth broker** (a self-hostable [Shoo](https://shoo.dev)): Google sign-in → a **domain-scoped, EdDSA-signed JWT** that any app verifies with a standard JOSE library against the published JWKS — no SDK, no SaaS, no cross-app tracking (the subject is `HMAC(secret, google_sub | origin)`, so the same person is a different, unlinkable id at every app). One ~76 kB binary; composes `machweb` (signed cookies) + `sso.src` (the OAuth dance) + the crypto builtins (`ed25519_sign`/`ed25519_pub`, `hmac_sha256`, `base64`) — **no new machin builtin**; the EdDSA JWT/JWKS are hand-built and verified against standard tooling.
- **[machin-playground](https://github.com/javimosch/machin-playground)** — **[▶ try machin in your browser](https://play.intrane.fr)**. Write MFL, hit Run — it compiles to **WebAssembly** and runs **client-side** (a Web Worker + a ~30-line WASI shim that captures `println`), so user code executes in the browser's wasm sandbox, never on the server. The whole thing is **one machin binary** (machweb) serving the editor page + a `/compile` endpoint (`machin build --target wasm`, bounded: ≤24 KB, no FFI, timeouts). Building it drove a fix into machin — wasm reactor modules now flush stdout ([machin#274](https://github.com/javimosch/machin/pull/274)).
- **[boilerplate-cli-ui-machin](https://github.com/javimosch/boilerplate-cli-ui-machin)** — a single-binary CLI serving an embedded React web UI + JSON API, with a background daemon via the C FFI. The machin entry in the [SuperCLI](https://github.com/javimosch) boilerplate family (smallest binary at ~27 KB).
- **[mfltok](https://github.com/javimosch/mfltok)** — an **exact GPT tokenizer** in pure MFL: real byte-pair encoding over the real `cl100k_base` / `o200k_base` rank tables, **byte-identical to [tiktoken](https://github.com/openai/tiktoken) across ~166k conformance cases** (hand-picked edges, 20k seeded fuzz per encoding, *exhaustive* whitespace strings, and an exhaustive Unicode letter-class corpus). The first text-processing/ML-adjacent tool in the ecosystem, and a demonstration that an **exact algorithmic port** — not an approximation — is practical in MFL with no library to lean on. Three things had to be built from nothing: the pretokenizer patterns need `\p{L}`/`\p{N}`/`\p{Lu}` and a negative lookahead, which **POSIX ERE (`regex_*`) cannot express**, so the alternation is implemented directly over **generated, binary-searched Unicode range tables** (42 kB of deterministic MFL); o200k's letter classes overlap on `{Lm,Lo,M}` so `U* L+` genuinely **backtracks**; and both vocabularies contain tokens with an **embedded NUL**, so ranks are keyed by hex — a raw-bytes `map[string]int` key silently truncates. Exercises `map[string]int` + the `bytes` builtins at scale, and **out-encodes tiktoken's Rust core by ~1.2×** (72 ms vs 87 ms on 445 kB, identical output) — ~1.7× end-to-end, no interpreter to boot — after removing a `bytes_sub`+`to_hex` allocation per probe from the merge loop. Still behind on memory (105 MB vs 68 MB), and says so. Written to delete the `chars/4` heuristic from [token-optimizer-cli](https://github.com/javimosch/token-optimizer-cli), measured undercounting real tokens by **18.6 %** — and non-uniformly, so it skewed the ranking, not just the totals.
- **[machin-blob](https://github.com/javimosch/machin-blob)** — a binary **blob inspector & patcher**: reads typed fields (`i32`, `f32`, `str`) at exact byte offsets via `peek_i32`/`peek_f32`, patches hex values at offsets, slices byte ranges. Drove **low-level memory ops** (`alloc`, `free`, `poke_u8`, `peek_i32`, `peek_f32`, `poke_i32`/`poke_f32`, `poke_ptr`) into the CLI-tool domain.
- **[machin-healthcheck](https://github.com/javimosch/machin-healthcheck)** — a concurrent HTTP status/latency checker. One goroutine per URL, results over a channel. Drove `dial`/`now_ms`/`parse_int` into machin.
- **[state](https://github.com/javimosch/state)** — an **agent-first system health CLI**: reports OK / CAUTIOUS / CRITICAL from CPU load (`uptime`), RAM (`free -m`), and disk (`df -h`) usage against configurable thresholds. `state config set --cpu-warn/--cpu-crit/...` persists per-user thresholds at `~/.config/state/config.json`; `state --json` and nagios-style exit codes (0/1/2) make it a drop-in health check for agent polling loops or cron. Ships `guide`/`help-json` (cli-guide-spec / cli-output-spec). One ~53 KB static binary, no daemon.
- **[veil](https://github.com/javimosch/veil)** — **[▶ docs](https://javimosch.github.io/veil/)** · an **agent-safe secret manager**: AES-256-GCM envelope encryption (master KEK wraps per-secret DEKs), X25519 sealed responses, deny-by-default path-based ACLs, and **mandatory output scrubbing** — `veil exec` captures child stdout/stderr and replaces every known secret with `***` before emitting, so agents run commands with secret env injection but never see the raw values. `veil resolve` returns opaque `VEIL_SEALED:...` tokens agents can't decrypt; `veil get` refuses stdout by default. A clean-room reimplementation of the Phoenix Secrets concept that fixes its three critical flaws (exec leaked via `syscall.Exec`, resolve/get printed raw values, MCP plaintext was the default). Ships `guide`/`help-json` (cli-output-spec). One ~82 KB static binary, no runtime.
- **[machin-gen](https://github.com/javimosch/machin-gen)** — a **template engine**: replaces `{{key}}` placeholders with values, supports transform pipelines (`{{name|upper|reverse}}`) via MFL's first-class **closures** stored in a `map[string]func` dispatch table. Transforms: upper, lower, reverse, trim, len, hex. Drove **closures** (`func` values, `[]func`, `map[string]func`) and **piped transforms** into the ecosystem.
- **[machin-hexdump](https://github.com/javimosch/machin-hexdump)** — a binary **hex viewer**: classic hexdump format (offset / hex / ASCII sidebar), configurable width, colored output. Drove **`bytes`** builtins (`read_file_bytes`, `byte_at`, `to_hex`, `bytes_str`) and the `byte_to_hex` pattern into the CLI-tool domain.
- **[machin-ssg](https://github.com/javimosch/machin-ssg)** — a static-site generator (markdown subset → HTML). Drove native file I/O and a parser fix into machin.
- **[machin-fetch](https://github.com/javimosch/machin-fetch)** — a tiny HTTPS client CLI (a pocket `curl` for `https://`). GET/POST, single binary. Drove **native TLS** (`https_get`/`https_post`, OpenSSL) into machin.
- **[machin-wscat](https://github.com/javimosch/machin-wscat)** — a tiny duplex WebSocket (`wss://`) client CLI (a pocket `websocat`). Stdin → send, recv → stdout. Drove a **native WebSocket client** (`wss_open`/`send`/`recv`/`close`, RFC 6455 over TLS) into machin.
- **[machin-linkcheck](https://github.com/javimosch/machin-linkcheck)** — a concurrent link checker that classifies each URL (OK / 4xx / 5xx / unreachable) and exits non-zero on broken links. Drove **error handling** into machin: `http_get` returning `(status, body, err)` plus `exit`.
- **[machin-hasher](https://github.com/javimosch/machin-hasher)** — a concurrent file-hasher (a parallel `sha256sum` for a directory), built to dogfood machin's **inferred data-race freedom** (`--race-safe`, v0.91.0) against a real program: `hasher.src` is race-free by construction (share by communicating, each worker returns results over a channel); `examples/racy-hasher.src` is the realistic bug (a shared map instead of a channel) — `machin check` catches it at compile time with `RACE001` and a precise counterexample, zero annotations. Surfaced a real compiler bug along the way: `read_file_bytes` segfaulted on a directory path (any `list_dir()` entry can be a subdirectory) — fixed upstream in machin v0.98.0.
- **[machin-jq](https://github.com/javimosch/machin-jq)** — a tiny `jq`-style JSON path query CLI (`.a.b[0].name`). Pairs with machin-fetch for a native HTTPS→query pipeline. Drove a **JSON path engine** (`json_get`) into machin.
- **[machin-pool](https://github.com/javimosch/machin-pool)** — a bounded-concurrency URL checker: a fixed worker pool racing results against an overall deadline. Drove **`select`** (multi-way channel waits, timeouts) into machin.
- **[machin-pipe](https://github.com/javimosch/machin-pipe)** — a streaming parallel fetch pipeline: producer → workers → fan-in, each stage terminating by closing its channel. Drove **channel `close`** + range-over-channel into machin.
- **[machin-batch](https://github.com/javimosch/machin-batch)** — groups a line stream into JSON-array chunks by size or by timer (flushing the rest on EOF). Its `select` over input + ticker drove the **comma-ok receive** (`v, ok := <-ch`) into machin.
- **[machin-http](https://github.com/javimosch/machin-http)** — a multi-command HTTPS client (`get`/`post`/`head`) with short+long flags and auto `--help`. Drove a reusable **flag parser** (`framework/flags.src`) into machin.
- **[machin-grep](https://github.com/javimosch/machin-grep)** — a regex line matcher (pocket `grep`): match/invert/count/only/line-numbers over a POSIX ERE. Drove **regex** builtins (`regex_match`/`find`/`groups`/`replace`) into machin.
- **[machin-jwt](https://github.com/javimosch/machin-jwt)** — a JWT decoder: decode header/payload (base64url JSON) and extract a claim. Drove **base64** builtins (`base64_encode`/`base64_decode`) into machin.
- **[machin-hmac](https://github.com/javimosch/machin-hmac)** — compute/verify HMAC-SHA256 (or SHA-256) signatures — webhook verification (GitHub/Stripe). Drove **hash** builtins (`sha256`/`hmac_sha256`) into machin.
- **[machin-wc](https://github.com/javimosch/machin-wc)** — a `wc` clone (lines/words/bytes), matching coreutils. Drove **`read_stdin`** (slurp stdin verbatim) into machin.
- **[machin-kv](https://github.com/javimosch/machin-kv)** — a persistent key-value store (set/get/del/list), data surviving across runs. Drove **SQLite** builtins (`sqlite_open`/`exec`/`query`/`close`) into machin.
- **[machin-cron](https://github.com/javimosch/machin-cron)** — a cron-expression evaluator: prints the next N times a crontab line fires. Drove **`time_fields`** (decompose a Unix timestamp into calendar fields) into machin.
- **[machin-date](https://github.com/javimosch/machin-date)** — a `date(1)`-style timestamp formatter (output matches GNU `date`). Drove **`time_format`** (strftime over a Unix timestamp) into machin.
- **[machin-mcp](https://github.com/javimosch/machin-mcp)** — a **Model Context Protocol (MCP) server**: JSON-RPC 2.0 over stdio transport, exposing 6 tools (echo, now, read_file, write_file, list_dir, sqlite_query). The smallest MCP server in the ecosystem — 31 KB static binary, no Node/Python runtime. Composes `json_get`/`json()` for JSON-RPC, `input()`/`println()`/`flush()` for stdio, `sqlite_open`/`sqlite_query` for databases, `read_file`/`write_file`/`list_dir` for filesystem — no new builtins.
- **[machin-meet](https://github.com/javimosch/machin-meet)** — a minimal self-hostable **Calendly for one person**: a single binary (HTTP + SQLite + embedded booking page) serving free slots, `.ics` files, and signed manage/cancel links, with booking alerts via **machin-notify** (Discord/Telegram) or WhatsApp. Drove **`time_make`** (build a Unix timestamp from calendar fields) into machin, completing the time trio.
- **[lume](https://github.com/javimosch/lume)** — **[▶ docs](https://javimosch.github.io/lume/)** · a **tiny agent-friendly git-like VCS** in one MFL binary: SHA-256 content-addressed objects, SQLite-backed staging, JSON-first CLI (`init`, `add`, `status`, `commit`, `log`, `branch`, `checkout`, `show`), short-hash support, and a minimal HTTP push/pull/clone protocol. Clean-room implementation inspired by Lit.
- **[machin-qs](https://github.com/javimosch/machin-qs)** — a URL query-string ⇄ JSON converter (decode to a JSON object, or build a percent-encoded query from `key=value` pairs). Drove **`url_encode`/`url_decode`** (RFC 3986 percent-encoding) into machin.
- **[machin-notify](https://github.com/javimosch/machin-notify)** — a notification **hub** (daemon + CLI): configure Discord webhooks / Telegram bots once, then apps `POST /notify {token, channel, message}` to one local endpoint — no provider integration or secrets in each app. machin-meet sends booking alerts through it.
- **[machin-cms](https://github.com/javimosch/machin-cms)** — an **agent-first headless CMS** (a CLI-based Strapi-lite) in one MFL binary: define collection schemas, CRUD data with typed validation, manage **RBAC** (users/roles/permissions), and expose chosen collections through a **REST API daemon** — backed by SQLite, MySQL/MariaDB, or MongoDB (one env var picks the store). Agent-first I/O (JSON on stdout, structured errors on stderr, semantic exit codes 80–119, `help-json`). Drove the **`system`** and **`sha1_bytes`** builtins (+ a pure-MFL **MySQL** driver) (run a shell command / spawn a detached daemon) into machin.
- **[machin-share](https://github.com/javimosch/machin-share)** — a self-hostable **file & paste drop** (a private `transfer.sh`) in one MFL binary: drop a file (or paste text) and get a share link; list / download / inline-view / delete. Files on disk, metadata in embedded **SQLite**, no Node/object-store. Drove **file uploads** into machweb (v0.76.0): **binary-safe requests** (`req.body_bytes`), **`multipart/form-data` parsing** (`parse_multipart`/`multipart_file`/`multipart_field`), arbitrary response headers (`with_header`, for `Content-Disposition`), and the **`bytes_index`** / **`write_file_bytes`** / **`remove`** builtins. Verified a binary upload→download round-trips byte-for-byte (matching SHA-256).
- **[machin-live](https://github.com/javimosch/machin-live)** — a self-hostable **live event & log stream hub** in one MFL binary: producers `POST /push/<topic>`, browsers/curl subscribe over **Server-Sent Events** (`GET /stream/<topic>`) and watch events arrive live; topic filtering, in-memory history replay, a live web console. Drove **streaming responses** into machweb (v0.77.0): `sse(fn)` + `sse_data`/`sse_event`/`sse_comment` (write a body incrementally over a long-lived socket) and **ignoring SIGPIPE** (a vanished client can't kill the server). Cross-goroutine fan-out via the idiomatic **lock-free hub goroutine** (a `chan` inside a struct, a `[]Sub` registry) — verified for fan-out, filtering, history replay, and disconnect survival.
- **[machin-deploy](https://github.com/javimosch/machin-deploy)** — a **production-ready reference machin web service**: one binary behind a reverse proxy (nginx/Caddy/Traefik/Cloudflare), wired correct + safe. Drove **reverse-proxy awareness + hardening** into machweb (v0.78.0): `scheme`/`client_ip`/`base_url` from `X-Forwarded-*` (`set_trust_proxy`), `Secure` cookies, a `413` body cap, read timeouts (anti slow-loris), JSON access logs, plus the **`peer_addr`** / **`socket_timeout`** builtins. Ships a systemd unit, a slim Dockerfile, and nginx/Caddy configs; new `machin guide --skill deploy`. Verified direct-vs-proxied scheme/IP, Secure cookies, `401`/`413`, and access logs end-to-end.
- **[machin-rooms](https://github.com/javimosch/machin-rooms)** — a self-hostable **real-time chat server** in one MFL binary: multi-room WebSocket chat with broadcast fan-out, join/leave notices, and a live member count. Drove a **WebSocket *server*** into machweb (v0.79.0) — the symmetric half of the wss client: the RFC 6455 upgrade handshake (`base64(sha1(key+GUID))`) + a **pure-MFL frame codec** over `bytes` + bitwise ops (`ws(req, fn)`, `ws_next_text`, `ws_send_text`, masked-client unmask), riding machweb's new generic **`hijack`** response (no new builtin). Lock-free hub-goroutine fan-out, two goroutines per connection; verified multi-client broadcast + room isolation against the Python `websockets` client.
- **[machin-mail](https://github.com/javimosch/machin-mail)** — a self-contained **SMTP toolkit** in one MFL binary: **send** mail (an SMTP client) and **catch** it (a local SMTP sink + a web inbox, MailHog/Mailpit style), so the sender is testable with **zero external deps**. Drove an **SMTP toolkit** into machin (v0.80.0, `framework/smtp.src`): `smtp_send` (full `EHLO`/`AUTH LOGIN`/`MAIL`/`RCPT`/`DATA`/`QUIT`, base64 auth, multi-recipient, dot-stuffing) + `smtp_recv` (the server side of a session) + a buffered line reader — pure MFL over `dial`/`read_bytes`/`base64`, no new builtin. Agent-first `send` CLI; verified both directions against Python stdlib `smtplib`.
- **[machin-hook](https://github.com/javimosch/machin-hook)** — a self-hostable **webhook relay + live inspector** in one ~80 kB binary (webhook.site + smee.io, no Node/Docker/hosted dependency): capture any request to `/hook/<id>`, watch it land **live** in the browser (Server-Sent Events), inspect headers + body, **replay** it to any URL, or **forward** it to your local app. The first **flagship app** of the adoption push — a thing a stranger would deploy because "one tiny binary on a $4 VPS" is the point. Composes `machweb` (HTTP + **`sse`**) + SQLite + the native HTTP client (`http_request`) for replay/forward; ~330 lines, captured payloads render via `textContent` (no XSS). **No new builtins** — proof the language already composes into a real, deployable web app.
- **[machin-db-migrate](https://github.com/javimosch/machin-db-migrate)** — a **SQLite ⇄ MongoDB** migration CLI, both directions, in one pure-MFL binary (no driver, no `mongoexport`). Drove a pure-MFL **MongoDB client** into machin — the **OP_MSG wire protocol** + a **BSON codec** ([`framework/mongo.src`](https://github.com/javimosch/machin/blob/main/framework/mongo.src) + [`bson.src`](https://github.com/javimosch/machin/blob/main/framework/bson.src)). `sqlite2mongo` reads the table's `PRAGMA` schema → typed BSON docs; `mongo2sqlite` infers columns from the first document → parameterized inserts; verified by a `SQLite → Mongo → SQLite` round-trip.
- **[machin-watch](https://github.com/javimosch/machin-watch)** — a tiny **uptime monitor**: polls URLs on a per-watch interval and alerts on every up↔down transition (with recovery time) through **machin-notify**. Composes `http_get` + SQLite + `sleep` — no new builtins; closes the loop (deploy → notify → monitor).
- **[machin-pomo](https://github.com/javimosch/machin-pomo)** — a terminal **Pomodoro timer**: live ANSI rendering, keyboard controls (pause/resume/skip/quit), configurable work/break durations, automatic long-break scheduling. Drove **`raw_mode`/`read_key`** (cbreak/no-echo + non-blocking single-key reads) into the CLI-tool domain: the terminal-input layer every future TUI inherits.
- **[machin-qr](https://github.com/javimosch/machin-qr)** — a terminal **QR code generator**: encodes text into a scannable QR code via MFL's C **FFI** (`libqrencode`), rendered with ANSI background colors. Drove **`extern`** (FFI declarations), **raw memory access** (`peek_i32` for struct fields), and **pointer reconstruction** (64-bit little-endian from two i32 halves) into the ecosystem.
- **[machin-revproxy](https://github.com/javimosch/machin-revproxy)** — a **reverse proxy**: route HTTP requests to backend servers by path prefix, with header rewriting (Host, X-Forwarded-*) and prefix stripping. ## Game dev

> See the [game-dev north star](https://github.com/javimosch/machin/blob/main/docs/NORTH-STAR-GAMEDEV.md) and the [`machin-gamedev` skill](https://github.com/javimosch/machin/blob/main/skills/machin-gamedev/SKILL.md).

- **[machin-escouade](https://github.com/javimosch/machin-escouade)** — a top-down tactical game whose units are triangles, squares and rectangles, **and whose soldiers have faces**. The bet is that immersion in a strategy game does not come from the unit art but from knowing *who* you just got killed: a triangle labelled "LCPL HALLORAN, scout car, K.I.A." is a person, the same triangle with an index for a name is a token. So the board stays deliberately abstract and every drop of fidelity is spent on the roster — a photograph, a surname, a rank, and a card that **goes dark and stays on the strip** rather than quietly disappearing. The shapes are chosen for what they *say*, not what they resemble: at the scale a tactical map is actually read — forty units, one screen — a silhouette can carry three bits and no more, so a **triangle points** (infantry shows its facing), a **rectangle is long** (armour shows you the flank you are trying to get to), and a **square has no orientation**, which is exactly right for a soft-skin. Side sets the hue and state sets the brightness so the two channels never collide. **Nothing in `assets/` was drawn.** All 74 images — 32 portraits, 8 unit sprites, 25 scenery objects, 9 ground textures — come out of a pipeline that drives the Gemini web app through **[linux-use](https://github.com/javimosch/linux-use)** on a private X display: **there is no API key and no language model in the loop**, because the account is already signed in inside a browser and the browser *is* the API. Seven job files, one command, resumable. Two design properties do all the work: **skip any job whose outputs exist** (a queue stopped by a quota limit, a refusal or a closed laptop restarts with the same command, and one refusal never costs the other six), and **keep every captured sheet** with a `--recut` that re-slices without generating — so a bad *slice* costs seconds instead of a generation, which it did twice in one session. And **ask for a grid, never for an image**: one prompt yields sixteen assets, not as a quota trick but because a model will not honour an aspect ratio and will not return sixteen files, whereas a square canvas cut into 4×4 is sixteen squares whatever it decided to draw inside them — and the cutting is arithmetic, which cannot fail in an interesting way. Sprites come back on flat magenta and are keyed locally, with two non-obvious requirements: **measure the key colour** off a ring around each tile's own border (asking for `#FF00FF` gets you *approximately* magenta — a vignette, a gradient, ringing), and **un-mix the feathered band rather than darkening it** (an edge pixel is `a·subject + (1−a)·key`, so the subject is `(observed − (1−a)·key)/a`; the fudge-factor version leaves a fringe that is invisible at 100% and unmistakable at the 12% a game actually draws a sprite at). Four failures on the automation side were silent and produced plausible output, which is why they are documented rather than merely fixed: **`import -window root` captures whatever is stacked on top**, and a headless game frame rendering on the same display wrote a sheet of *game pixels* that sliced into nine perfectly clean, perfectly unusable roofs — fixed twice over, by capturing the browser's own window by id *and* giving the generator its own display; **`pkill -f <flag>` matched the developer's own Edge**, which runs with the same `--force-renderer-accessibility` for unrelated work; **pressing Return in the composer silently fails roughly one time in three**, so submission now verifies itself by looking for the prompt in the *conversation* rather than trusting the keystroke; and the image's own **Download button cannot be fired synthetically at all** — `act` returns ok and does nothing, `click` demonstrably lands (the tooltip appears in a screenshot) and does nothing — so the sheet is taken off the screen at the rectangle AT-SPI reports for the image element, scrolled into view with **wheel events, which work where `Page_Down` does not** because the chat's scroll container never takes keyboard focus. **The generated art is laid *over* the primitives, never in place of them**: under every sprite there is still a disc in the side's hue, a ring in the state's, a bar for strength and a fan of sparks for suppression, `F1` switches the units back, and the repo ships a screenshot of the same frame with `assets/` emptied — a screenshot rather than a compatibility claim. The engine is **[machin-ressort](https://github.com/javimosch/machin-ressort)**'s, and the reuse is the surprise: it is a *side-view platformer* engine, and the useful half turned out to be entirely orientation-agnostic — flow-field pathfinding, `grid_los`, the camera with `cam_unproject`, particles, HUD primitives and the PNG loader all carried a top-down RTS unchanged, with three additive FFI functions contributed back (`DrawTexturePro`, because `DrawTextureEx` rotates about the *top-left corner* and so anything that turns has to go through Pro). The rules are three units and one design decision — **armour is subtracted from damage, not multiplied into it** — so rifles *scratch* a tank and can never kill it, while a tank hits five times harder and five times more slowly, and cannot enter a hedgerow at all. Terrain is four values doing three separate jobs on purpose: movement (`grid_pass` tests **the mask bit indexed by the cell value**, so a hedge is impassable to armour without a single special case in the pathfinder), sight (stops at stone only — the village is the one feature that can hide a tank from a tank), and cover (scrub is 45% harder to hit, road is 10% *easier*, so the fast lane is the killing ground). Suppression is a second health bar because "hurt" and "pinned" are different problems. The 113 headless assertions earned their place by **failing three ways on their first run and finding two bugs no screenshot would have shown**. Units walked into buildings, and the line-of-sight test was *innocent*: `grid_los` samples every third of a cell and cannot miss a cell the ray passes **through**, but a diagonal that clips a wall's **corner** spends less than that inside it and is sampled straight past — so the steer was honestly reported clear while the path shaved the stone, the unit's centre landed where the flood is −1 with no way downhill, it recovered to the nearest legal cell, aimed at the same waypoint and clipped the same corner again, forever, five cells short. No finite sampling step fixes it (the time inside the corner goes to zero), so the *mover* slides on whichever axis is free — which is also what makes a unit follow a wall instead of sticking to it. And one battlefield in twelve opened with a tank that could not reach the fight: two wrong fixes went in before the right one, and the actual cause was that **copses were painted after the roads and overwrote them**, severing the very lane that had just been added to prevent it. On the map, the single biggest visual fix was a **scale** error rather than an art one — drawing a whole 256px texture into each 32px cell makes every cell read as its own patch, and a stubble field came out looking like brickwork, so one texture now spans sixteen cells with each cell taking its own source sub-rectangle, and the tiles are mirror-tiled so they repeat with no seam. Fields are a **patchwork of five crops** by region, because a map where every field is the same green reads as a lawn however good the grass is; the village is a **street with frontages** rather than a scatter of blocks; an orchard is a three-cell lattice, the one terrain where a section can fight a tank on level terms *and* the one that cannot enclose anything, so it costs the connectivity guarantee nothing; and scenery is **derived from the grid at draw time and never stored**, with hedgerow-or-tree decided by whether a scrub cell's neighbours line up on one axis — which turns the generator's hedge lines into continuous treeline and its copses and orchards into woodland without either ever being labelled. Determinism is by construction: every roll is a **hash of the moment** (the tick and the two unit indices) rather than a draw from a stream, so a shot cannot land differently because an unrelated unit died first. Honest about its limits — the AI is three rules deep on purpose (an opponent that re-plans every tick produces units that *vibrate*, which reads as less intelligent than one committing to a bad plan for two seconds), the mirror-tiled stubble has a findable symmetry axis, two of the eight unit sprites came back on a diagonal and the offset is measured once in code rather than argued about with the model at a generation per attempt, and the asset pipeline needs a signed-in browser and a display and is not CI-able and is not meant to be.

- **[machin-amerrissage](https://github.com/javimosch/machin-amerrissage)** — *amerrissage*, a landing on water: **a spaceplane, an ocean planet, and no seam between flying and floating.** The claim is that seamlessness is not a transition but the *absence* of one — no mode flag, no trigger volume, no swap from a flight model to a boat model. One integrator and three forces that go to zero on their own: gravity `g₀(R/r)²`, drag proportional to density, buoyancy proportional to submersion. **Density is a field, not a mode** — zero in vacuum, exponential through the atmosphere, a thousand in the sea — so re-entry heating and a hull slowing in water are the same `½ρv²` with a different number in it. And the claim is stated so it can be falsified: "the worst acceleration step is small" only encodes how sharp the author was willing to tolerate, so the suite flies the same descent at 60 Hz and 240 Hz and checks that the worst step *shrinks with the timestep* — a steep-but-continuous force does, a mode switch does not move at all. **The flight model is a rebuild, and the rebuild is the story.** The first attempt carried Euler angles against the *local* frame and integrated body rates as though they were Euler-angle derivatives — true only at zero bank, which is exactly the case that matters, because an aeroplane turns by banking and pulling and in the body frame that is a pitch rate which has to come out as world yaw. Rolled over and pulling, she did nothing at all; pitch also had to be clamped short of vertical to dodge gimbal lock. Now the attitude is **carried, not parameterised**: two orthonormal world vectors, nose and canopy, integrated by the angular velocity and re-orthonormalised each step, with pitch/bank/heading derived for the instruments and never fed back — orthonormal to **0.0 ppm through a full loop**, 118 frames through vertical with no singularity, holding a 45.6° bank and turning at `g·tan(bank)/V`. Eight distinct errors came out of that rebuild and **every one was found by printing a trace, not by reading the code**: ninety degrees of sideslip at t=0 (initial velocity set on a world axis while the nose pointed elsewhere); an inverted roll axis; control powers sized by eye that gave 1175°/s of roll; linear moment coefficients extrapolated past the stall, which made a departure unrecoverable rather than merely unpleasant; a **`Cn_β` with the wrong sign — the aircraft was directionally unstable**, so any sideslip amplified itself and yaw ran away to 1.7 rad/s in a second; a proportional α-loop that **cannot** hold an angle of attack on a statically stable aircraft (the stick that *holds* 5° is one the error term only reaches when the error is large — she mushed down at 16 m/s with the loop reporting itself satisfied, which was the stall present from the first second of every flight); a commanded α beyond what the elevator could trim, saturating the stick; and on splashdown a **pitch rate of nine million rad/s in one frame**, because density jumps eight hundredfold at the waterline and explicit Euler is stable only while `k·dt < 2`. That last one is fixed by integrating damping implicitly — `q = (q + drive·dt)/(1 + k·dt)`, one divide, unconditionally stable. **Precision is settled by measurement, not folklore:** MFL's `float` is a double, so a millimetre is resolvable three thousand kilometres from the planet's centre and the simulation is exact at any altitude — it is `rlVertex3f`'s f32, whose step out there is a quarter of a metre, that forces a floating origin at *draw* time only. **The sea is machin-houle's, laid on a sphere** by one projection shared by the physics and the mesh, drawn as a five-ring clipmap where each ring is three times the last and each wave component fades out where the mesh cannot carry it — mip-mapping, and pointedly the *opposite* operation to houle's failed ripple experiment. Wave content reaches 5.8 km where a single graded grid managed 390 m, and the trap on the way was instructive: stretching one grid to 6.5 km put 46-metre cells 180 metres from the ship, buying distance by destroying the near water. Clouds are soft-particle billboards sampling a 3D density field — genuinely volumetric, coarsely integrated, which is the honest ceiling with no shader; each puff is a *fan* rather than a quad, because a quad's four corners are all on the rim and cannot have a soft centre. Three engine silences are documented for the next repo: **raylib's default far clip is 1000 m** (every earlier game in this family fitted inside it by accident, and the first that did not rendered a sky and a ship and nothing else), raylib 5.0 has no `rlSetClipPlanes` so the projection is rebuilt with `rlFrustum`, and **`rlgl` is a batching API for the third repo running** — a backwards winding made all 976 cloud billboards emit exactly zero pixels. Honest about what it cannot do: distant open water still reads flat beyond ~200 m, and the geometry is no longer the reason — at grazing angles Schlick fresnel saturates toward 1, so every facet reflects almost pure sky whatever its slope, and fixing it needs the per-pixel normal variation the engine provably cannot provide.

- **[machin-houle](https://github.com/javimosch/machin-houle)** — **a motorboat, two hundred metres of open water, and a sea that is computed rather than animated.** The rule the repo exists to enforce: **wavelength is primitive, speed is derived.** In deep water a wave's phase speed is fixed by its length — `ω = √(gk)` — so a long swell *must* outrun a short chop and there is no choosing otherwise; offer both as knobs and the sea looks wrong in a way nobody can point at. There is exactly one knob, **wind speed**, and the wavelengths (Pierson–Moskowitz peak), amplitudes, phase speeds and directional spread are all consequences of it. It is the same class of mistake as the stride bug two repos ago, where gait phase was advanced by time instead of distance: parameterising something the physics had already determined. **Nothing about the boat is animated either.** The hull is four points; each asks the sea how deep it is and pushes back; heave, pitch and roll fall out of the four answers, and **no line in the boat file mentions rolling** — take a wave on the beam and the port samples are deep while the starboard ones are in air, and she heels. Two details decide whether it reads as a boat or a cork: **a hull at rest floats at its waterline**, so lift at zero submersion is already her whole weight and *grows* as she is pushed under (lift merely proportional to depth balances weight only half a metre down — an invariant caught her cruising along submerged in a flat calm); and **a propeller in the air produces nothing**, which turns out to be most of why a rough crossing takes longer. That last one was not the first answer: surge from the wave slope, the textbook mechanism, very nearly cancels over a wave cycle and moved the crossing time by two hundredths of a second. Measuring is what found the real term. One invariant does two jobs — a Gerstner surface folds over itself when `Q·A·k` exceeds 1, and keeping the summed budget under 1 both stops the sea self-intersecting *and* is exactly the condition under which the **Newton inverse solve** for "how high is the water above this fixed point" converges in three passes (exact even in a gale, where the fixed-point version it replaced was still 20 cm out after four). Drawing it is where the engine's real economics show: every vertex goes through the FFI one call at a time, so cost is linear in triangles — **0.40 µs each, brought to 0.28** by colouring **per node rather than per corner** (each node is shared by up to six triangle corners, so shading at emit time did the reflection, the fresnel, both specular lobes and the haze six times for the same point) and by emitting **`RL_QUADS` rather than two triangles** (four vertex emissions a cell instead of six, and each emission is two FFI calls). 25,088 triangles in half a 16.7 ms frame. The look is a deliberate, **measured** partial port of **Morrowind's** water: its DX7 environment-mapped bump mapping put the detail in the surface normal — the quantity lighting actually reads — **per pixel**, and half of that transfers. The lighting half does, and is the whole improvement: reflect the view vector about the normal, read a sky *gradient* along the reflected ray instead of one flat colour, Schlick fresnel at water's 0.02, a tight `dot⁴⁸` sun glint with a very small broad sheen, and distance haze so the horizon stops reading as the edge of a table. **The bump half does not, and the negative result is the point:** a ripple spectrum was written, wound into the vertex normal, and A/B'd against a build without it — the two frames were *indistinguishable*. A vertex colour is not a sample of a smooth function, it is a corner of a flat triangle, so vertex spacing is the sampling rate for **shading** exactly as much as for geometry; below Nyquist the sea became crumpled foil, and band-limited it cost seven trig calls a vertex and bought nothing. Half-metre detail near the boat would need vertices every 12 cm — 400k of them over a 40 m radius. Because whether water *looks* right is the one thing here no assertion can settle, sixteen look values are on a **live tuner** (`TAB`, arrows, shift-for-fine) whose `ENTER` prints the current set back as MFL source to paste into the defaults. Everything that *can* be settled by an assertion is: eight invariants and six tests, all headless — the surface cannot fold at any sea state, phase speed falls with wavelength, the inverse solve converges, she floats rather than submerges, a gale costs time, a **beam** sea rolls her harder than a following one, and the helm turns her the way the screen says. Three of those were written as failing assertions first and two found real bugs on the way to passing — including two angle conventions in one program (the sea as `(cos, sin)`, the hull as `(sin, cos)`, each natural in its own file) that silently rotated every sea by ninety degrees, so a beam sea was a following one and rolled her *less*: exactly right for a following sea, and exactly the opposite of what the test asked for.

- **[machin-ressort-splinter-cell](https://github.com/javimosch/machin-ressort-splinter-cell)** — a character animated **entirely by arithmetic**: no spritesheet, no clips, no frame table and no blend tree. A 16-joint skeleton is posed each frame from a handful of continuous numbers — speed, crouch depth, aim direction, how far through a jump he is — and drawn as tapered runs of discs by forward kinematics, with two-bone **inverse kinematics** placing the hands and feet. Six locomotion gears are ONE gait whose stride, cadence, stance fraction, lean and arm swing are all functions of speed, so 2.7 m/s produces the gait for 2.7 m/s rather than the nearest clip. Two ideas carry it: the gait phase advances by **distance travelled** rather than by time (which is what stops the feet sliding), and **the feet lead while the hips follow** — a planted foot is motionless in the world, the legs solve backwards from it, and the pelvis sits at `sqrt(L²-x²)`, so the rise and fall of walking is geometry rather than a tuned curve. The same IK gives aiming at any pixel, a crouch whose knees fold because a leg has nowhere else to go, a ledge climb where the body hangs *from* the hands, a vault for anything below half his height, and a ladder climbed hand-over-hand. Because animation cannot be judged from a screenshot — and the thing writing it cannot watch it either — it ships **contact sheets** (`--strip`, `--poses`, `--climb`, `--vault`) and **108 headless assertions** on the properties a viewer would complain about: that a planted foot does not slide, that no knee bends backwards, that the hips rise and fall, that consecutive steps differ. Character fidelity was reached by putting a game frame beside a reference sprite in front of a vision model six times and implementing each round's measured critique.

- **[machin-brick](https://github.com/javimosch/machin-brick)** — *(deprecated POC)* **build a robot out of bricks, and the walk falls out of what you built.** Every game in this family animates by arithmetic rather than by clips, and the gait rules have never actually known what a body is — they know leg length, hip width, foot positions, cadence. This is the honest test of that: the player hands over a pile of bricks and the program has to work out whether it has legs, how many, how long they are and what it weighs, and then the same rules apply. **Cut the graph at every hinge and flood from the core**: what you reach is the hull, every island still hanging off a hinge is a limb, its end is the brick furthest from the joint, and what it ends in decides what it is — a foot makes it a leg, a wheel makes it a wheel, a gun makes it an arm. Two legs is the biped gait from four games ago, four is a trot, six is alternating tripods, and one solver runs all of them: the only genuinely new code is four lines saying which legs are down together. **Nothing in the game is a typed-in stat.** A part says how heavy it is, how much it can take and what it does; speed is motor torque over total mass, steadiness is how far apart the feet are against how high the mass sits, recoil is the weapon's impulse applied at the distance that brick sits from the centre. So a tall stack on two legs is quick and tips over, a wide four-legged platform is slow and can fire a rail gun without knocking itself down — **and it knocks itself down if you build it narrow** — and nobody balanced any of it. **Damage is brick removal.** A shot takes apart the brick nearest where it landed, the connectivity flood drops whatever is no longer attached to the core — shoot a shoulder and the arm goes with the gun on it — and the machine is derived again from what is left, so **a quadruped that loses a leg walks away on three because the solver is now solving a three-legged problem**, not because anybody animated a limp. There is an assertion for exactly that and it reads `so it moves differently (trot to crawl)`. Auto-battle, with behaviour derived too (a rail-gun build keeps its distance; one that loses its rail gun starts advancing), and `--sim 9` runs battles with no window, which is how ten opponents will get balanced. 45 headless assertions, including that a planted foot does not slide and no leg over-reaches **on two, four and six legs** — the last of which caught the foot lead being half what it should be (`lead = step × stance`, a derivation got right in the previous repo, written in its README, and then halved here: on a hexapod it put ninety-six feet a frame further from their hinge than the leg was long). Abandoned with the technology working and the game not: the workshop is clumsy above one layer, limbs have no knees, and the ten prefab opponents and the pick-one-of-three unlock — which is where the game actually was — were never built. The parts worth taking elsewhere are the derivation, the N-legged gait, and **the narrated fight**: eight named states with a reason recorded for every transition, `--trace`, `--dump` and per-tick invariants, which found five bugs on its first run, four of them already shipped — including a trace that lied because six of the eight state names had lost their case labels.

- **[machin-front](https://github.com/javimosch/machin-front)** — a **WWII strategy POC where every soldier on the field walks differently**, because every one of them is generated rather than played back. A hundred and twenty men, a hundred and twenty bodies, a hundred and twenty gaits, and none of it stored: a soldier is a body seed, a walk seed, a position and an order, and everything visible is recomputed from those forty bytes every frame. A clip-based game cannot do this — it would need a hundred and twenty walk cycles authored, so it ships one and plays it a hundred and twenty times, which is why a section in a strategy game reads as a formation of clones. The figure is [machin-lowpoly](https://github.com/javimosch/machin-lowpoly)'s, **referenced rather than copied**: one generator, two programs. **Deaths are generated too** — fifty men dying identically is the same failure as fifty walking identically, and worse, because the dead stay on screen: a death is the skeleton at the *instant of the hit* (mid-stride, whichever foot was forward), the direction the round came from, his own seed for the twist and the limbs, and a curve that accelerates and settles. Two skeletons and a curve between them, which is not a ragdoll and at this camera is not distinguishable from one. **Pathfinding is one flow field per squad, not A\* per man**: twelve searches would find one optimal path and file down it, where a BFS flood costs O(cells) once per order, O(1) per man per frame, and twelve men take different lines because they start in different cells. The interesting engineering problem is that every triangle is still computed in MFL and streamed a vertex at a time, so: seven levels of detail chosen by distance from the camera's EYE, ending in a **per-joint impostor** — six boxes strung on his own joints, 48 triangles, still walking his own walk, needing no pre-rendered views because the animation is already in the skeleton; **animation LOD** where distant men are stepped every third frame at three times the interval, which is *exact* rather than approximate because the gait phase advances by distance travelled; settled bodies drawn two levels coarser than the living (140k triangles to 57k after an engagement); a clamped zoom, so the two most expensive levels stop being reachable by accident; and a ground with its own four levels of square, grid-aligned rings — round rings tested on cell centres tile with holes, and the field came out peppered with rectangles of sky. **120 men at 39,000 triangles and 60 fps.** **Cover is not an object** — a hedge and a wall differ by height and passability — and **one sight test** answers both what a vision cone reaches and what may fire, stopping at anything taller than the ray is *where that thing stands*, so a man prone behind a hedge is below the ray at the hedge even though the ray clears it on the way past. Cover is then the **Company of Heroes** model: hard cover is DIRECTIONAL, so flanking is the absence of the enemy's cover rather than a bonus; light cover is not; negative cover exists, because a game whose worst case is "no cover" gives you no reason to look at the ground; and a crater works from every direction because it is a hole. A man under fire looks for better ground every few seconds, sustained suppression **pins** him (he stops moving and shooting and takes less damage, which is what stops pinning being a delayed death), and squads **bound** — half moving while half fires. The worst bug it ever had is a good rule: **terrain that costs something is a decision, terrain that forbids something is a trap** — an impassable stream had an army walk to the bank and stay there, so water is passable at four times the cost, which sends a section to the ford and made the flow field weighted, which made plain BFS wrong and Dial's algorithm right. 68 headless assertions, the load-bearing ones being that **no two men share a walk** and no two die the same way — claims easy to believe from a screenshot and wrong — and that **drawing the same dead man two hundred times leaves him where he was**, which is not an assertion about deaths but about aliasing: a skeleton is a handful of slices, `s = s0` shares them, and a stored pose that is drawn rather than copied gained the terrain height once per frame and sailed into the sky. It looked like a physics bug and it was an `=`.

- **[machin-lowpoly](https://github.com/javimosch/machin-lowpoly)** — a **soldier generator and animation editor** in 3D, and the first repo in this family to draw a real mesh: a rigged humanoid glTF is converted by `tools/mkbase.py` (decimating on a **graded grid** — four times finer on the head and hands, where the PS2/Xbox era's own assets put a third and a fifth of their budget) and then **skinned by the engine's own 21-joint skeleton**, so the walk, the two-bone IK and the pelvis/shoulder counter-rotation carry over from the side-scrolling games untouched — they were always about joints, not geometry. **No mesh, texture or clip is committed**: the pipeline is the deliverable and the body you feed it is yours. Clothes are **cut from the body itself** — the figure's own triangles in the region a garment covers, pushed out along their posed normals — so a sleeve follows the arm exactly and deforms with it for free; a triangle is clothed if *two* of its three corners are, because requiring all three leaves a ring of bare skin one triangle wide at every cuff. The 512² atlas is **painted pixel by pixel at load** from the same seed: irises, lashes, brows and a mouth (painted, never modelled — which is what that generation did), camouflage in hard bands, a weave at two frequencies, folds, a placket with buttons, boot laces. It generates **seven WWII armies**, and an army is a helmet, a load and a colour in that order of importance: six helmets — Stahlhelm, Brodie, M1, SSh-40, Adrian, field cap — each five or six rings differing only in brim width and skirt depth, because those two measurements are all a forty-pixel silhouette can carry and the Brodie's flat plate is unmistakable from directly above, which is the camera a strategy game uses. Weapons generate the same way the body does (a rifle draws 1.06–1.16 m because that is the range the real ones occupied) and **the hands are the constraint**: a carry position is two hand targets and the arms are solved backwards to them, because posing arms and hoping the weapon lands in the grip misses by centimetres every frame. A **walk is sixteen numbers** from its own seed, and the panel that displays them **is** the editor — drag any bar, clamped to the generator's own ranges, so a hand-tuned walk is still a walk. A **gait is a stance and a speed** (stand/crouch/prone × still/slow/normal/fast) because that is how a strategy game gives an order; prone gets its own builder, crawling left-arm-with-right-knee, since "the walk but very low" is a man sliding on his heels. **Modes are distributions, not states** — march, combat, stealth — so twelve men under one order are not one animation played twelve times. Model and animation save as **separate files of generator inputs**, so a walk fits whatever body it is loaded onto and never needs retargeting, and decimation previews at four levels (9,349 → 2,588 triangles) before export. 89 headless assertions. The two most expensive bugs are both about reading a number in the wrong frame: **a ring's `t` runs from the PARENT joint**, so the crown of the skull is `t = 4.6` on a head bone that is a three-centimetre stub — read the other way, every helmet dome lands inside the skull and looks exactly like radii that are too small; and **a stride is two steps** — driving the gait phase with the step length instead halves every pace, which reads as a shuffle, looks like something to tune, and is an off-by-two. Both are now printed by `--headinfo` and `--gaitinfo` rather than guessed from renders.

- **[machin-ressort-vr](https://github.com/javimosch/machin-ressort-vr)** — the same procedural automata as [machin-ressort-thief](https://github.com/javimosch/machin-ressort-thief), **seen from above**: a top-down stealth-action POC (*Gates of Hell* meets *Metal Gear*) where one change of camera turns three things from decoration into mechanics. **Cover is a line of sight and a HEIGHT** — a block has one, a machine has an eye height, and a sight ray is stopped by anything taller than the ray is *where the block is*; there is no cover system, no in-cover state, just two block heights and three stances. Interpolating the ray along its length gives the property that makes a map readable: **cover works where you are, not where they are**. `T` draws the sentry's cone, and it is not an impression of the check — it is the same `map_ray` at the same eye height, so crouching behind a barricade leaves the drawn cone reaching you while it stops seeing you. **If it cannot see you it cannot shoot you**: a round travels at the shooter's eye, so one rule covers both. Movement is a vault (one cell, must be low, far side clear — and it *shows more of you*, which is its cost), a **dive** that ends prone with the pistol out, and a **roll** that is the only thing in the game which evades a round; both slow time, and time is a consequence of having committed rather than a button. The gait rule from the side-scrolling games carries over intact — **the phase advances by distance travelled**, feet are world positions that do not move while planted, and walking into a wall stops the legs. Maps are editable text with nine cell kinds over two heights. Because a plan view cannot show height, the **body is drawn displaced from its own footprint** with the legs bridging the gap, which is what makes the three stances readable at thirty pixels; `--sheet` puts all sixteen states side by side, and the first thing it showed was that six of them were the same picture. 122 headless assertions — including a flood that proves the exit is reachable *and* that sealing the barricades makes it unreachable.

- **[machin-ressort-thief](https://github.com/javimosch/machin-ressort-thief)** — *(finished POC)* a **Thief-like** built on the [machin-ressort-splinter-cell](https://github.com/javimosch/machin-ressort-splinter-cell) figure, whose one claim is that there is **exactly one light model** and both the screen and the guard's eye are readings of it. Each lamp casts 288 rays once at load and remembers how far each got; that fan *is* the light — drawn as a triangle fan, and sampled onto the grid the AI reads — so a point is lit if it is nearer the lamp than the fan reaches in its direction, and dousing a lamp darkens the picture and the perception in the same statement because they are the same array. `visibility()` is illumination × exposure × motion, all three already state the figure carries, and the number the guard uses is the number shown in the **light gem**, so every death is legible. Around it: sound as gait × floor surface losing three metres per wall (so "two doors away" is quieter than "one door away" and nothing in the model knows what a door is — the lintels are boxes and the ray counts them); an **awareness ladder** derived from one meter and never set by an event, so a guard cannot skip a rung and hearing alone is capped below certainty; three ways to hide, of which the crawl space needs **no special case at all** (it is a void between two ordinary plates, so light and sight stop for the reason they stop at a wall); a blackjack that only works from behind on a man not already looking; and one authored 21-room house where the furniture *is* the level design — over waist height it stands against the back wall and stops light but not bodies, under it you vault. The figure is cast as a **clockwork automaton**, which turns the gait's mechanical evenness from a flaw into the point. 156 headless assertions, including that the drawn shadow edge and the sampled one are the same line, and that a bookcase stops the light while not stopping you.

- **[machin-gta](https://github.com/javimosch/machin-gta)** — a **top-down GTA 1** on the [machin-ressort](https://github.com/javimosch/machin-ressort) engine, and the first game in the ecosystem where **nothing is authored**: ten vehicles, the people, the pickups and every sound come out of a seed. The city is generated *offline* by subdivision — cut the map with a street somewhere off-centre, recurse — so streets never line up across the plan and you get T-junctions, streets that stop after three blocks, parks and alleys; it is written as run-length **JSONL** (168² cells, 14 kB) and re-skinned at load, so the plan can be diffed and hand-edited. Routing is a **breadth-first flood from the destination** that everything heading there walks downhill (one flood serves an entire police force); vehicles are ten silhouettes generated from one spec that also decides their handling, drawn through a **64-heading sprite bake** with the paintwork palette-swapped so ten colours cost one bake. **All the audio is synthesised by the game itself** — a WAV writer built on `write_file_bytes` + `from_hex` (MFL cannot append a byte, so samples are built as hex text), band-limited wavetables, an eight-bar loop, and an engine note that is one buzz pitch-bent by road speed — with on-device TTS ([supertonic](https://github.com/supertone-inc/supertonic)) for the two speaking parts. Because an agent cannot hear what it writes, it also ships an **ear**: forty assertions measuring crest factor, attack/decay, spectral centroid, periodicity (which catches aliasing) and the largest step between adjacent samples (which catches an instantaneous edge) — then nine deliberate defects to prove the checker bites, two of which the first version missed. 162 headless assertions total.

- **[machin-ressort](https://github.com/javimosch/machin-ressort)** — the **2D engine** underneath machin-gta, and an agent-first **sprite toolchain**: Torque2D-style declarative scenes over a deterministic 60 Hz sim with a synced/unsynced split, so a playthrough records to a 2 kB text artifact and `verify` replays it headlessly and proves the same per-frame checksum. - **[machin-stickman-battle](https://github.com/javimosch/machin-stickman-battle)** — a **2D ragdoll-physics fighting game**: stickmen built from Verlet point-masses + bone constraints fight with **momentum** — a fast fist deals speed-scaled damage and knocks the opponent's ragdoll back, so *the physics is the hitbox*. Built as an **active (motorized) ragdoll** in the Euphoria / GTA-IV mould: bounded muscles hold a fighting stance over the feet (best effort), balance genuinely **fails** when the torso is knocked past the feet (the stickman falls), then an **automatic get-up** raises it — physics and player input still perturbing the recovery. 9 modular `.src` files (physics / fighter / action / input / ai / combat / render / game). Extends the verlet sandbox into a real balance controller; built by the self-hosted machin.
## Web

> machin does both ends of the web in one language — a native server (machweb) and a reactive WebAssembly UI — no Node/bundler. The agent how-to is the [`machin-web` skill](https://github.com/javimosch/machin/blob/main/skills/machin-web/SKILL.md); the direction is the [web north star](https://github.com/javimosch/machin/blob/main/docs/NORTH-STAR-WEB.md). (Web *services* like [machin-meet](https://github.com/javimosch/machin-meet) and [machin-ssg](https://github.com/javimosch/machin-ssg) are listed under CLI tools & services.)

- **[machin-web-ui](https://github.com/javimosch/machin-web-ui)** — **[▶ live gallery](https://javimosch.github.io/machin-web-ui/)** · an **agent-first design system for isomorphic machin apps** (shadcn-style): one binary that scaffolds an SSR + reactive-wasm app (`init`), vendors component source you own (`add` — 39 components: app shells, drawers, dialogs, tables, no-JS `peer-checked` form controls, date/nav/feedback primitives), and generates the stylesheet with a built-in **pure-MFL Tailwind-compatible CSS engine**: 3,600+ classes **differential-tested rule-for-rule against the real tailwindcss binary** (a dev-only oracle — corpus, scanner, cascade order, byte-identical preflight), 16 ms vs 1,342 ms on the same corpus, 172 kB vs 43 MB, **no Node**. `list`/`coverage`/`check` answer in JSON — the binary is the docs. The gallery is the design system dogfooding itself, statically exported to GitHub Pages and driven by a headless-Chrome E2E.
- **[machin-saas-demo](https://github.com/javimosch/machin-saas-demo)** — **MachNotes**, an end-to-end **SaaS in one binary**: the whole backend stack wired together — **OAuth2/OIDC SSO** login ([`sso.src`](https://github.com/javimosch/machin/blob/main/framework/sso.src), with a bundled mock identity provider so it runs locally), **sessions in Redis** (session id → email, TTL; [`redis.src`](https://github.com/javimosch/machin/blob/main/framework/redis.src)), a **parameterized Postgres** notes table ([`postgres.src`](https://github.com/javimosch/machin/blob/main/framework/postgres.src)), signed cookies + routing ([`machweb.src`](https://github.com/javimosch/machin/blob/main/framework/machweb.src)), and a **reactive WebAssembly UI** ([`reactive.src`](https://github.com/javimosch/machin/blob/main/framework/reactive.src) → wasm, keyed-list patches). Login → store note → reactive list → logout, verified end to end. The backend capstone — proof a single static MFL binary is a credible SME backend (HTTP + auth + SQL + cache), no Node/cgo/client-libs. Concurrency-safe via connection pooling (the gap it surfaced, added in machin v0.65.0). See the [backend north star](https://github.com/javimosch/machin/blob/main/docs/NORTH-STAR-BACKEND.md).
- **[boilerplate-cli-ui-machin-isomorphic](https://github.com/javimosch/boilerplate-cli-ui-machin-isomorphic)** — a **starting point for isomorphic web apps in machin**: one static native binary that is a CLI, an HTTP server, a JSON API, and serves its own **reactive WebAssembly UI** — the whole app (server, client, shared model) in MFL, no Node/bundler. The example poll is **server-rendered** (works with JS off), then **hydrated** by a wasm client where signals + a computed total + templating drive surgical DOM updates; `models.src` is compiled into *both* ends. Composes everything: `machweb` + `flags` + `reactive` + `--target wasm` + binary-body serving. The full-stack-MFL capstone.
- **[machin-web-demo-router](https://github.com/javimosch/machin-web-demo-router)** — a **multi-page SPA** with client-side routing: three pages, no-reload navigation, working back/forward + address bar, and deep-links (refresh on `/users`). The router ([`framework/router.src`](https://github.com/javimosch/machin/tree/main/framework), on top of reactive) makes the active route a **signal** (an int index); an `outlet` reaction re-renders the active page, `link`/`navigate` switch routes, and path strings flow host→wasm via `ptr_str`. One page is reactive — a counter whose state **persists across navigation** (it's a signal). A catch-all machweb server serves the shell for any path. All MFL.
- **[machin-web-demo-users](https://github.com/javimosch/machin-web-demo-users)** — a **CRUD back-office** (manage a users database): one native binary that is a CLI + HTTP server + **SQLite**-backed JSON API + reactive wasm UI (list / add / toggle active / delete). The server owns the data (`sqlite_query` → JSON rows, `?`-bound params); the client is a reactive *view* — the host fetches `/api/users` and hands the JSON to the wasm (`ptr_str` + `json_get`), a keyed list patches only changed rows, a computed shows the active count, and a form adds users. The SPA-over-API counterpart to the isomorphic boilerplate; the worked "manage my users DB" recipe.
- **[machin-web-demo-todo](https://github.com/javimosch/machin-web-demo-todo)** — a reactive **todo app with real text input**: state, logic, and rendering all in machin, compiled to wasm. The new piece is a working `<input>` — the typed UTF-8 flows *into* the module (machin v0.57's **`ptr_str`**: the host writes the text into wasm memory at an `alloc`'d pointer, machin reads it). Signals + a computed "active" count + a **keyed list** (re-keyed by `id*100+done` so a toggle re-renders just that row) + templating. Adding inserts one row, toggling re-renders one, deleting removes one — no `innerHTML` churn. Rounds out the toolkit with **forms**.
- **[machin-web-demo-reactive](https://github.com/javimosch/machin-web-demo-reactive)** — **fine-grained reactivity** (the Solid/Leptos model, in MFL): a reactive list whose **state and view logic live entirely in machin** — **signals**, a **computed** sum, live bindings, and a **keyed list** that emits only the DOM deltas (`insert`/`remove`/`reorder`), no `innerHTML` replacement, no virtual-DOM diff. The runtime ([`framework/reactive.src`](https://github.com/javimosch/machin/tree/main/framework)) auto-tracks which reactions read which signals, recomputes only the affected ones, and patches only when the rendered text/keys actually change — sorting the list emits *only* a reorder, no item re-render. Drove **`[]func`** (slices of closures) into machin (v0.53.0) and **computed + keyed reconciliation** (v0.54.0); composes package globals (the signal store) + `--target wasm`.
- **[machin-web-demo-ssr](https://github.com/javimosch/machin-web-demo-ssr)** — **isomorphic server-side rendering**: a counter page rendered by a single native machin binary (machweb), where the view logic lives in a shared `view.src` that *also* compiles to the wasm client — **one component model, two runtimes**. The server's HTML and the wasm client's re-render are byte-for-byte identical (same `view()`). SSR needs **no JavaScript** (the +/− controls are plain server-round-trip links); the wasm client adds an instant SPA from the same source. No Node, no bundler — `machin encode` + `machin build`. The full-stack-MFL direction: write a component once, run it on the server for first paint and in wasm for interactivity.
- **[machin-web-demo-wasm](https://github.com/javimosch/machin-web-demo-wasm)** — **machin on the frontend**: an interactive counter whose entire view (markup, `n²`, a recursive `fib`) is written in MFL, compiled to **WebAssembly**, and rendered live in the browser — the way Rust does with Yew/Leptos, here **MFL → C → wasm** reusing machin's C backend. `zig cc` (clang + wasi-libc, one binary) cross-compiles the emitted C to a `wasm32-wasi` reactor module with zero WASI imports, so it loads in a bare page. The DOM bridge **is machin's own FFI, both ways**: exported MFL functions are wasm exports JS calls into; an `extern "env"` block becomes a wasm import the host supplies (machin → `innerHTML`). Composition — machin reaches the browser with no new language primitive, only a leaner emit. The first **frontend** dogfood; see the [web north star](https://github.com/javimosch/machin/blob/main/docs/NORTH-STAR-WEB.md).
- **[machin-web-demo-serve-tls](https://github.com/javimosch/machin-web-demo-serve-tls)** — a REST + SQLite notes API terminating HTTPS **itself**, no reverse proxy, via machin's native **`serve_tls`** (v0.92.0) — same router/handler/`Response` machinery as `serve`, just swap the call. Both build modes verified: dynamic, and `--static` (SQLite amalgamation + an embedded CA root bundle, verified end to end in a genuinely empty Docker `FROM scratch` image).
- **[machin-web-demo-mongo-tls](https://github.com/javimosch/machin-web-demo-mongo-tls)** — a links REST API on a **pooled MongoDB connection** (`mongo_pool_init`/`mongo_acquire`/`mongo_release`, concurrency-safe against `machweb`'s per-request goroutines) served over **`serve_tls`** — two "each request is a fresh goroutine" concerns combined for the first time. Stress-tested with 20 concurrent `POST`s against a 4-connection pool: all persisted correctly, nothing wedged or corrupted. Also documents an investigation dead end (a convincing-looking pool bug that turned out to be a stale test process, not machin) — reported rather than swept under the rug.
- **[machin-web-demo-wasm-tls](https://github.com/javimosch/machin-web-demo-wasm-tls)** — a reactive counter compiled to wasm, served (HTML shell **and** `.wasm` binary both) by one machin process over native **`serve_tls`** — no reverse proxy, no Node. `ok_wasm`'s binary response path had never actually served a real wasm module over a real TLS connection before this; verified byte-identical delivery (`sha256sum` against the on-disk file) and full interactivity (signal → computed → DOM patch on click) in a real headless-Chrome session. Also documents a composed-framework trap: `reactive.src` declares its full DOM-op import set unconditionally, so a wasm host must stub `list_insert`/`list_remove`/`list_order` even for an app that never calls `list()` — wasm import resolution is link-time, not lazy.

## Crypto & protocols

> The pure-MFL layers behind the native WhatsApp client stack (see the case study below).

- **[machin-protobuf](https://github.com/javimosch/machin-protobuf)** — a protobuf wire-format inspector (`protoc --decode_raw`-style) + reusable codec library, implemented in pure MFL over the **`bytes`** type. Exercises machin's binary surface (bytes + crypto + binary WebSocket) built out for a native WhatsApp client.
- **[machin-noise](https://github.com/javimosch/machin-noise)** — a [Noise Protocol](https://noiseprotocol.org) **XX handshake** (`Noise_XX_25519_AESGCM_SHA256`, the pattern WhatsApp uses) in pure MFL over the `bytes` + crypto builtins, with a loopback self-test. The transport-encryption layer for a native WhatsApp client.
- **[machin-wabin](https://github.com/javimosch/machin-wabin)** — the **WhatsApp binary-node (stanza) codec** in pure MFL: token-dictionary compression (from [whatsmeow](https://github.com/tulir/whatsmeow)), nibble/hex packing, the node tree. Encoder output is byte-for-byte WhatsApp-compatible. The stanza-framing layer for a native WhatsApp client.
- **[machin-signal](https://github.com/javimosch/machin-signal)** — the **Signal Double Ratchet** (X3DH + ratcheting cipher) in pure MFL, key schedule matching [libsignal](https://github.com/tulir/libsignal-protocol-go) exactly, with a loopback self-test. The message-encryption layer for a native WhatsApp client.
- **[machin-wapair](https://github.com/javimosch/machin-wapair)** — WhatsApp **device-pairing crypto** (the ADV account/device signature exchange) in machin, modeling [whatsmeow](https://github.com/tulir/whatsmeow)'s `pair.go`. Drove **`xeddsa_sign`/`xeddsa_verify`** (Curve25519 XEdDSA signatures) into machin.
- **[machin-signtool](https://github.com/javimosch/machin-signtool)** — a generic message signing CLI (`keygen`/`sign`/`verify`, Ethereum-style address derivation) on machin's **`keccak256`/`secp256k1_*`** builtins (v0.88.0), exercised outside the EIP-712 lens they were originally added for (unblocking [`javika-machin`](https://github.com/javimosch/javika-machin)'s Polymarket order signer). `secp256k1_recover` doing the actual verification is the same math Solidity's `ecrecover` uses.

## Case study: a native WhatsApp client stack

The most demanding dogfood: building **every cryptographic and wire-format layer of WhatsApp natively in machin** — a goal that looked impossible for a young language with no bignum, no crypto, and NUL-terminated strings. It's assembled and verified offline in **[machin-whatsapp](https://github.com/javimosch/machin-whatsapp)**, whose end-to-end self-test runs a message through the whole pipeline (`plaintext → protobuf → Signal ratchet → WhatsApp stanza → Noise transport →` and back).

The five layers, each a standalone pure-MFL library pulled from the real protocol sources ([whatsmeow](https://github.com/tulir/whatsmeow), [libsignal](https://github.com/tulir/libsignal-protocol-go)):

| layer | tool | drove into machin |
|---|---|---|
| transport | [machin-noise](https://github.com/javimosch/machin-noise) — Noise XX handshake | (composes the crypto builtins) |
| framing | [machin-wabin](https://github.com/javimosch/machin-wabin) — WhatsApp stanza codec | (pure MFL over `bytes`) |
| body | [machin-protobuf](https://github.com/javimosch/machin-protobuf) — protobuf codec | (pure MFL over `bytes`) |
| messages | [machin-signal](https://github.com/javimosch/machin-signal) — Signal Double Ratchet | (libsignal-exact key schedule) |
| pairing | [machin-wapair](https://github.com/javimosch/machin-wapair) — ADV pairing crypto | **`xeddsa_sign`/`xeddsa_verify`** |

Getting there grew the language itself: **`bytes`** (v0.34) → the **crypto suite** (v0.35) → **binary WebSocket** frames (v0.36) → **declarable `bytes`** (v0.37) → **XEdDSA** (v0.38). It stops at the live connection on purpose — wiring an unofficial client to WhatsApp's servers risks an account ban — so everything is verified offline by loopback/round-trip.

## In the machin repo

- **[`framework/`](https://github.com/javimosch/machin/tree/main/framework)** — reusable MFL modules: `machweb` (a backend web framework — router, response builders, JSON, binary bodies), `reactive` (a fine-grained signals + patch-list runtime for wasm frontends), and `flags.src` (a CLI flag parser), each composed ahead of your app with `machin encode`.
- **[`examples/`](https://github.com/javimosch/machin/tree/main/examples)** — runnable programs: a raylib **GUI** game menu, JSON-over-HTTP servers, generics, concurrency, FFI, and more.

## Why these exist

machin's current direction is **dogfooding**: build real tools, hit real gaps, and grow the language to fill them. Each app above added capabilities to machin itself — that's the point. To contribute an app, build something real and send a PR here with the link.

Several tools ship an agent **`SKILL.md`** at the repo root (e.g. [machin-meet](https://github.com/javimosch/machin-meet/blob/master/SKILL.md), [machin-notify](https://github.com/javimosch/machin-notify/blob/master/SKILL.md)) — a focused, agent-facing guide to operating, integrating, and deploying the tool, including hard-won gotchas. Run `machin guide` to master the language itself.
